# Web 图标适配

> [English](web-icon.md) | 简体中文

## 范围与决策

- **REQUESTED — Max，2026-08-30**：“web 也要适配上 icon”。
- **完成标准**：favicon、Apple touch icon、顶栏品牌、连接卡片和空聊天欢迎页都使用仓库里的 Ferry 图标；不再有字母占位。
- **不做**：重新设计图标，改动布局、API、鉴权、iOS 或 Android。
- **深度**：focused；两个 Web 生产文件和两张内嵌 PNG 资源，加一个静态资源测试。
- **决策**：复用提供的 64 px 和 256 px PNG 两个尺寸。页面内的装饰性图片使用空的 alt 文本，因为旁边的 Ferry/标题文字已经说明了它们的上下文。

## 冻结检查清单与证据

1. 两张 PNG 都已内嵌，以 `image/png` 提供，并解码为恰好 64×64 / 256×256 — `TestHandlerServesIconAndReferencesItFromPage`。
2. HTML 恰好包含一个顶栏和两个欢迎页 `<img>` 引用，没有旧的字母占位 — 同一个测试加 `rg 'ferry-icon|>F<' internal/webui`。
3. 真实浏览器证明加载后的原始尺寸、28/48 px 的渲染尺寸，且没有字母占位 — browser-harness 当前工作树记录。
4. 免密码时间线和需要密码的连接卡片在深色模式下都渲染出图标 — `/tmp/ferry-icon-qa.png` 和 `/tmp/ferry-icon-access-qa.png` 视觉检查。
5. Go tests、JavaScript 语法、`git diff --check`、独立的聚焦评审、push、测试服务器 Docker 重建和部署后的浏览器检查都通过。

## 作者对抗式评审

两轮之后的结论：**ship candidate；作者已知范围内没有未解决的 P0/P1/P2**。第 1 轮发现测试只验证了 64 px 文件。独立评审随后证明两个 URL 仍可能提供同一张小 PNG 而测试不会失败；第 2 轮加上了精确的解码尺寸和精确的 `<img>` 数量。

1. **耦合状态** — 没有改动定时器、标志、缓存或应用状态；只改了内嵌字节、HTML 元素和对应的 CSS 选择器。证据：`git diff -- internal/webui`。
2. **失败路径** — 任一资源缺失/不是 PNG/尺寸不对，或缺少可见的 `<img>`，都会让 handler 测试失败；浏览器证据中两个尺寸都是 `complete=true` 且原始宽度非零。
3. **未改动的消费者** — `rg 'brand-mark|welcome-mark' internal/webui` 只找到更新后的 HTML/CSS 和测试；JavaScript 不依赖元素标签或文本。
4. **合约面** — 没有改动 API、DB、环境变量或鉴权界面；只加了同源的静态路径。证据：diff stat 限定在 `internal/webui`。
5. **原始复现** — 浏览器截图显示，Web 原本显示 `F` 的地方现在是提供的蓝色 Ferry 图标。
6. **旅程重放** — 当前工作树运行在生产 Go handler 的 `127.0.0.1:42819` 上；DOM 内容和截图都在最后一次生产代码修改之后读取。
7. **机制区分** — 把 256 px 的字节换成 64 px 的文件会让测试以 `dimensions = 64x64, want 256x256` 失败；还原后通过。浏览器尺寸和空的 textContent 排除了字母回退。
8. **回归扫描** — 候选回归是布局偏移和重复的无障碍名称；渲染尺寸仍是 28/48 px，装饰性的 `alt=""` 让旁边的标签保持权威。
9. **规模/边界** — 按用途定尺寸的 64/256 px 资源分别为 8/60 KiB；隐藏和可见的欢迎页变体都会加载，当前显示的那个渲染为 48 px。
10. **合约攻击** — 不适用：没有改动协议、schema、凭据或持久化边界。
11. **断言 producer** — `hidden` 仍由既有的接入/欢迎流程产生；两种可见结果都在浏览器里强制触发并观察过。
12. **被推翻的发现** — 不完整的资源测试让我们重新追问路径是否存在、内容是否一致、尺寸和位置：两个路径现在都检查状态码/MIME/签名/精确尺寸，HTML 检查恰好一加二的图片数量。
13. **轮次上限** — 作者证据不是最终绿灯；push 前需要一次独立的聚焦评审。
