## S1 — Design decision

### Evidence

- **Observed**：Go embeds the Web UI; `go test ./...` therefore covers the Server/Web package boundary, while Web asset tests cover embedded assets.
- **Observed**：Android already has an official Gradle wrapper and a passing offline test/lint/assemble command.
- **Observed**：the iOS project has shared targets but no committed scheme file; `xcodebuild -scheme Ferry` currently resolves the autogenerated scheme.
- **Observed**：Compose stores the complete durable state in one named `/data` volume; SQLite uses WAL, so a stopped-container archive is the narrow consistent-backup mechanism.
- **Observed**：GitHub's `macos-26` image currently provides Xcode 26.6, iOS 26 simulators, and iPhone 17 Pro devices.

### Candidates

1. **Selected — one workflow plus repository scripts**：CI calls the same Gradle, Go, Xcode and data-management entry points maintainers can run locally. This keeps policy executable without adding a task-runner dependency.
2. **Rejected — documentation only**：smaller, but backup, secret hygiene and cross-platform build promises would have no gate.
3. **Rejected — release framework/task runner**：Fastlane/Gradle publishing plugins or a Makefile layer add dependencies and another command vocabulary before store publication exists.

Plain brief: this work prepares Ferry's repository for collaborators without changing what the product does. It makes build checks and Docker data recovery repeatable, while leaving signing secrets and publishing under the maintainer's control. If it is wrong, contributors get misleading setup instructions or discover too late that a backup cannot be restored.

## S3 — Builder attack record

- **Two judges**：README commands and CI commands were compared for Go, Web, Android and iOS; the repository checker prevents the highest-risk documentation markers from drifting silently.
- **Extremes**：backup/restore exercised an empty service state, exact Ferry database/blob names, a changed volume, and an unexpected archive member. Existing archives and safety-backup paths fail rather than overwrite.
- **Equivalent spellings**：archive entries accept the backup tool's `./name` form only after removing one exact leading `./`; absolute paths, nested traversal and arbitrary names remain outside the allowlist.
- **Defaults**：Compose keeps loopback/high-port defaults; password remains a Web setting; absent release signing fails any task graph that packages a release but does not break debug CI.
- **Side doors**：restore copies the source to a private snapshot, then validates and extracts those same bytes before mutating the service volume; symlink entries and non-Ferry files are rejected.
- **Failure boundary**：after the safety archive is durable, restore clears the automatic-resume flag before replacing data; an extraction failure leaves Ferry stopped instead of serving a partial volume.
- **Signal boundary**：HUP/INT/TERM map to fixed non-zero exits before the common EXIT cleanup runs, so an interrupted operation cannot report success after cleaning up.
- **Policy gate**：`scripts/check-repo.sh` enforces the instruction symlink, ignored secret/data classes, historical pairing marker, shell syntax and license statement.
- **Supply-chain side door**：all third-party/official workflow actions are pinned to resolved commit SHAs; version comments retain update context without trusting mutable major tags at execution time.
- **No self-certification**：the Docker self-test used an isolated real Compose volume and reread restored bytes. Physical-device/LAN claims remain excluded and blocked.

Confirmed counterexample: the first iOS CI command ran the whole shared scheme, so two environment-dependent UI journeys failed on a clean machine even though all 20 unit tests passed. CI and README now select `FerryTests` explicitly; UI journeys retain their separate real-Server gate.
