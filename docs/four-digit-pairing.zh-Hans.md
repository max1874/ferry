# 四位数字配对（历史）

> [English](four-digit-pairing.md) | 简体中文

> Superseded on 2026-08-30：已被 `docs/password-access.md` 取代。当前产品不再使用配对码。

## 范围与决策

- 状态：`implemented`；iPhone 的手动领取等待用户确认。
- 需求（2026-08-30）：配对码应该是四位数字，因为现在的 code 太复杂，不好输入。
- 完成标准：Server、Web、OpenAPI 和 iOS 接受并展示恰好四位 ASCII 数字，包括前导零；code 仍然是十分钟有效、一次性使用。
- 不做：限流、针对敌意局域网的防护、设备 token 改动、持久化或 API 路由改动。
- 深度：contract，因为被接受的凭据格式在 Server、Web 和 iOS 之间一起改变。
- 预算：配对码生成器/归一化器、两个输入界面、OpenAPI、直接耦合的测试和文档，以及部署刷新；不新增持久化机制。
- **Decided — 用户，2026-08-30**：局域网是可信的；接受 10,000 个 code 的搜索空间，不加暴力破解防护。

## 设计

- **Observed**：改动之前，code 是 16 字符 base32、随机、十分钟有效、只在内存中、原子性一次性使用。
- **Selected**：用拒绝采样把两个随机字节均匀映射到 `0000`–`9999`，保留前导零。
- **被用户否决**：四位数字加按 IP 限流；它把可信局域网当作敌意环境，还加了用户不想要的状态。
- **Rejected**：六位数字；不满足明确的四位数字交互要求。

一句话说明：Ferry 会显示一个在手机上好输入的短 PIN。只改变 PIN 的字符集和长度；过期、一次性预留、签发者撤销和设备 token 都保持不变。如果实现发生漂移，某个界面会拒绝另一个界面给出的 code。

## 冻结检查清单

1. 生成的 code 匹配 `^[0-9]{4}$`，保留 `0000`，拒绝采样不会引入取模偏差。
2. 归一化只接受恰好四个 ASCII 数字，拒绝空白、错误长度、字母和非 ASCII 数字。
3. 既有的过期、碰撞重试、预留回滚、并发单一胜者和签发者撤销测试保持绿色。
4. OpenAPI、Web 约束、Server 和 iOS 数字键盘对四位 ASCII 数字达成一致。
5. 完整 Go tests、race tests、vet、签名的 iOS tests/build、Docker 构建和 `git diff --check` 通过。
6. `test-server:42817` 上的最终 Docker 镜像给出四位数字 code；真实 Web 和 iPhone 能领取一次，重放失败。
7. 七类攻击记录、13 项作者评审和全新零上下文合约结论中，没有未解决的 P0/P1/P2。

## 七类合约攻击

1. **双裁判** — Server 是最终裁判；机器可读的 OpenAPI 请求/响应 pattern、Web 的 `[0-9]{4}` 和 iOS「拒绝而不改写」的输入校验一致。证据：`rg` 在明确标为历史的设计记录之外，没有找到任何仍在使用的 base32/16 字符消费者。
2. **极值** — `0000` 和 `9999`、过期边界、错误长度和耗尽的随机数都有命名的鉴权测试覆盖。
3. **等价拼写** — 不存在：Server 拒绝两端空白、字母和全角数字；只接受恰好四个 ASCII 字节。
4. **默认值后门** — 十分钟和一次性这两个默认值没变；不限流是用户明确的决定，不是意外没设置的默认值。
5. **旁路** — 每一条领取路由都走到 `PairingManager.Reserve`；HTML/iOS 的过滤只是方便，不能绕过 Server 的归一化。
6. **策略需要门禁** — race tests、OpenAPI pattern、HTML pattern 和签名的 Swift 编译就是可执行的门禁。
7. **不自我认证** — 部署的 Web 生成了真实的四位数字，并在容器重建后保留了持久化状态；真机领取明确留给用户，而不是用 mock 宣称完成。

## 独立评审的更正

对候选版本 `200f890` 的第一次零上下文评审返回 FAIL，有两个 P1 和一个 P2；三条结论都被接受，没有豁免：

- 公网的 `FERRY_HOST_IP` 可以通过 Docker 端口发布绕过进程的监听检查。容器现在把发布主机传进 Ferry 的 Go 配置校验器；一个 `203.0.113.10` 的容器探针以 `published-host must be a loopback or private/link-local IP address` 失败关闭。
- iOS 之前会删掉无效字符并截断过长的粘贴值，可能把 `12a34` 变成另一个凭据 `1234`。它现在拒绝整个编辑并保留原来的字段值；一个签名的 Swift 测试覆盖了字母、上标数字、全角数字和五位数字。
- OpenAPI 的领取请求只在描述文字里说了四位数字。请求和响应现在都使用严格的机器可读 `^[0-9]{4}$`；Server 也拒绝空白，避免各校验器之间 Unicode 空白表不一致。
- iOS 允许编辑不完整的 PIN，但也允许提交它。Pair 按钮和 `AppModel.pair()` 现在各自独立地要求恰好四位 ASCII 数字；一个 model 测试证明 `123` 不会发出任何客户端领取调用。

对代码 commit `99b278c` 的最终零上下文验证返回 PASS，在 Go race/vet、签名的 20 项模拟器测试、Docker 敌意主机探针、语法检查和完整合约评审之后，没有 P0/P1/P2。唯一未完成的证明是用户用真实 iPhone 领取。
